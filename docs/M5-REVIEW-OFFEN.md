Verdict: M5 is close to done but not ready to commit. I read the public surface (feed, ICS, snapshot cache, canary), clone/carry_over, T09/T09b follow-up, search, library and palette. I ran no tests or gates. The ICS writer is solid: control characters are cleaned and escaped, lines fold at 75 octets, UID and SEQUENCE are stable, VTIMEZONE and the DST repeated-hour rule are covered. The view is allowlisted, the right filter sits in SQL, and the highlights come only from title and summary. Fix before the pilot: (1) the cache is not invalidated by venue/org/category edits or scan verdicts, so a venue that was just made private stays visible in feed and ICS for up to 2 h; (2) revert skips the derived-value step, so reverting a live dossier can publish an unconfirmed free venue text; (3) the palette shows create actions without event.create. The remaining findings are minor: reminder mail text, lost Redis claim, cross-org verify_format, facts and media carry-over for foreign templates, a11y scroll in the palette, an unreliable Ctrl+K frame check, no HEAD support, and the CODEOWNERS placeholder.

- **major** `backend/app/modules/admin/venues_router.py`:109: PATCH /admin/venues commits without invalidating the public cache. Flipping is_private or lowering public_precision changes public_event_v (venue_name/address/city), but events:feed:version is not bumped. The feed and every ICS snapshot keep serving the old address for up to public_snapshot_max_age_seconds (7200 s default), and the live path is bypassed while the snapshot is 'fresh'. Organization and category renames (admin organizations/categories routers) have the same gap. Poster scan results (worker/scan.py: infected/dead) also never bump the version. No test covers any of these. → Call invalidate_public(request.app.state.arq_pool) after commit in every admin write that feeds the view (venue, organization, category) and after a scan verdict on a poster of a public event. Add a test per source (venue private toggle, org rename, infected poster) that reads the feed right after the write.
- **major** `backend/app/modules/pipeline/revert.py`:100: Revert to an older revision writes plan.changes (including venue_text) but never runs the derived-value step of EventService._derived_values. Location precision and confirmation survive a text change: reverting a live dossier to a revision with a different free venue_text publishes that text (possibly a private address) as confirmed 'exact'/'building' without a new confirm-location. It also skips the facts-fit on a category change. all_day, starts_on and ends_on are not in CONTENT_FIELDS, so reverting starts_at/ends_at of an all-day event leaves stale starts_on/ends_on, and the feed and ICS then disagree about the dates. → Route revert through the same derived-values/allday.resolve helpers as EventService.patch (reset location_precision/confirmed_* when venue_text differs; fit facts; recompute all-day bounds). Add a revert test with a venue_text change on a live dossier asserting the feed shows no venueText.
- **major** `frontend/src/app/layout/palette/command-palette.component.ts`:70: Palette actions 'Neues Dossier' (a:new) and 'Aus Vorlage' (a:template) are listed for every signed-in person. Only a:format checks a permission. A viewer or member without event.create sees and can run actions that lead to a route they cannot use. The server rejects the write, but the lens 'keine Aktionen ohne Recht' is violated. The save-as-format check uses the global auth.can('event.submit') and ignores the open dossier's allowedActions. → Gate a:new and a:template with auth.can('event.create'). Gate a:format with the dossier's allowedActions ('save-as-format'), not only the global permission. Add specs for member and viewer.
- **minor** `frontend/src/app/layout/palette/palette.service.ts`:29: The Ctrl/Cmd+K handler is bound on the shell host for every frame (public, bare, pending), but the palette only renders in the 'rail' frame. On the login or public pages it calls preventDefault (hijacking the browser shortcut for nothing), sets requested/isOpen, and the palette then pops open unexpectedly after sign-in or navigation into the rail frame. → Ignore the shortcut unless frame()==='rail' (or auth is signed in), and reset isOpen on frame change.
- **minor** `frontend/src/app/layout/palette/command-palette.component.html`:28: Keyboard a11y: the list has max-height 55vh and overflow auto, but moving the active option with the arrow keys never scrolls it into view (no scrollIntoView or block:nearest anywhere in the palette). With 5 events, 3 formats, actions and about 8 nav entries the active option disappears off-screen, especially on phones (WCAG 2.4.7, 2.4.11). Search errors (429/503) are swallowed silently, so the person sees 'Keine Treffer' instead of an error. → On active-index change call document.getElementById(activeId())?.scrollIntoView({block:'nearest'}). Show a distinct state for search errors and for the 429 rate limit.
- **minor** `backend/app/modules/pipeline/service.py`:182: T09 by any actor calls verify_format on event.format_id with no permission check on the format's organization. A dossier cloned from a foreign archived template keeps the foreign format_id, so an organizer of org A archiving their own dossier dates and 'verifies' the master howto of org B (Format.last_verified_at plus the howto Document.verified_at). howto.verify in 'archived' does the same. The 'checked within 12 months' signal that PLAN 7.3 relies on can be written by anyone who has a dossier in that format. → Only call verify_format when the actor has event.submit or format.manage for format.organization_id. Otherwise skip it, or keep a separate per-edition verified mark. Add a cross-org T09 test.
- **minor** `backend/app/modules/notifications/templates/de/followup_reminder.txt.j2`:1: The reminder always prints 'Es fehlt noch: {{ missing }}.' Once every part is done and only the T09 click is left, missing is empty and the mail reads 'Es fehlt noch: .' (same in the html template). The mail also says the system archives 'even if something is still missing', which is wrong for a dossier that is complete. → Wrap the sentence in {% if missing %}...{% else %}Alles ist erledigt, es fehlt nur noch das Abschließen.{% endif %} in the txt and html templates. Add a render test for an empty list.
- **minor** `backend/worker/followup.py`:71: The Redis claim (SET NX, TTL 40 d) is written before the notification rows are committed and before the mails are dispatched. If session.commit() or dispatch_mails fails after the claim, the reminder is lost for that entry for good: the next hourly run sees the claim and skips it. The comment claims the claim only covers people with the inbox switched off, but it also gates everyone. → Set the claim after a successful commit, or delete the claim in an except path. Alternatively rely on the notification dedupe key and use the claim only for dispatch.
- **minor** `backend/app/modules/publicapi/ics/timezone.py`:1: The writer emits only a Europe/Berlin VTIMEZONE, but IcsRow.tzid comes from the DB column event.tzid, which has no CHECK constraint (only the API schema restricts it to Literal['Europe/Berlin']). A row written with another tzid (import, direct SQL) yields DTSTART;TZID=<other> without a matching VTIMEZONE, or a ZoneInfoNotFoundError that turns the whole all.ics into a 500 and takes every calendar down. → Add a CHECK tzid = 'Europe/Berlin' on event (or have ics_row coerce or skip unknown tzids). Add a unit test with a foreign tzid.
- **minor** `backend/app/modules/publicapi/ics_router.py`:50: The public GET routes (/ics/*.ics and /api/public/feed/events) do not answer HEAD (FastAPI GET-only gives 405). Several calendar clients and link checkers probe with HEAD before they subscribe. The unknown-slug 404 path hits the DB (public_category_v lookup) on every request with no negative caching, behind the cache layer that protects the known slugs. → Register HEAD (api_route with methods GET, HEAD) for the ICS and feed routes. Short-lived negative cache or the existing nginx limit_req for unknown slugs.
- **minor** `backend/tests/_support/canary.py`:1: The canary does not seed some internal sources: format.description_md and the master howto text, format.defaults, the org contact is only set on one org, no shared-but-restricted attachment (guarded only by the DB CHECK), no internal text in event.location_confirmed_by or in the sender subs of audit rows. Use a non-hex marker for the amount, for example a distinctive 11-digit number.

The report line 'facts: reset' in CARRY_OVER is also inaccurate, since only four keys are reset. → For relation=='foreign' reset protocolOwner, priceText and meetingPoint as well (or keep only capacity/ageLimit/min/max participants). Make the report line say what is kept. Extend test_facts_reset.

The test only checks attachment objects, not media refs. → For relation=='foreign' either strip /api/media/images/ links from the copied description_md or do not add refs for them. Add a test with an inline image in the foreign template.
